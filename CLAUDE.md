## Что должно уметь приложение

Всё, что связано с учёбой и студенческой жизнью, — в одном месте:

1. **Сегодня** — главный экран: пары на сегодня, горящие дедлайны, события вечера.
2. **Расписание** — подтягивается автоматически из РУЗ САФУ (см. раздел
   «Импорт расписания»): дата, время, предмет, тип занятия, аудитория,
   преподаватель. Можно вручную добавить или скрыть пару. Показывать замены:
   если пара изменилась с прошлой загрузки — пометка «изменено».
3. **Задания** — практические, лабораторные, семинары, конспекты, чтение хрестоматии.
   Поля: предмет, что сделать, дедлайн, статус (не начато / в работе / сдано),
   заметка, прикреплённые ссылки. Фильтры: по предмету, «на этой неделе», «просрочено».
4. **Предметы** — карточка предмета: преподаватель, контакты, требования,
   материалы (ссылки на ЭБС «Лань», методички, файлы), конспекты, список заданий.
5. **Конспекты и заметки** — Markdown-заметки, привязанные к предмету или проекту.
6. **Внеучебка** — проекты и события: студсовет, «Школа актива», репетиции,
   выступления, мастер-классы. У проекта — задачи, даты, заметки.
7. **Неделя / нагрузка** — календарь недели, где видно пары + задания + события
   вместе, и простой индикатор перегруза (сколько часов занято по дням).
8. **Помощники по оформлению работ**:
   - чек-лист оформления по СТО САФУ 2026 (поля 25/10/20/20 мм, TNR 12–14,
     интервал 1,5, отступ 1,25, подписи «Таблица 1. …» / «Рисунок 1. …»,
     раздел об использовании ИИ, сдача PDF через почту @edu.narfu.ru);
   - генератор библиографической записи по ГОСТ Р 7.0.100–2018
     (книга, статья, электронный ресурс, ЭБС с пометкой
     «Режим доступа: для авториз. пользователей.» и датой обращения).

## Технические решения

- **Тип приложения:** PWA (веб-приложение, которое устанавливается на телефон
  и компьютер как обычное приложение и работает без интернета).
- **Стек:** Vite + React + TypeScript, `vite-plugin-pwa`.
- **Хранение данных:** local-first — всё лежит на устройстве в IndexedDB
  (через библиотеку Dexie). Приложение обязано работать офлайн.
- **Синхронизация телефон ↔ компьютер (этап 5):** через Яндекс Диск
  (REST API / WebDAV) — один JSON-файл с данными, слияние по полю `updatedAt`.
  Зарубежные бэкенды (Supabase, Firebase, Vercel) не использовать: из России
  они работают нестабильно, особенно с мобильного интернета.
- **Резервная копия:** экспорт/импорт всех данных в JSON-файл (с этапа 1).
- **Хостинг:** GitHub Pages, автодеплой через GitHub Actions при пуше в `main`.
- Без регистрации и серверов на первых этапах.

## Импорт расписания из РУЗ САФУ

- Источник: открытое расписание `https://ruz.narfu.ru/` (без логина, официального API нет).
  - список групп школы: `https://ruz.narfu.ru/?groups&institution=<id>`
    (ВШЭУиП, вероятно, `institution=28` — проверить);
  - расписание группы: `https://ruz.narfu.ru/?timetable&group=<oid>`, где `oid` —
    внутренний номер, а НЕ номер группы 171606. Для Максима `oid` = **21077**
    (задать в конфиге `GROUP_OID`, чтобы потом можно было сменить группу);
  - на странице группы бывает ссылка на iCal (.ics) — если есть, парсить её
    (надёжнее HTML); иначе разбирать HTML.
- Браузер не может напрямую читать ruz.narfu.ru (CORS), поэтому схема такая:
  1. скрипт `scripts/fetch-schedule.mjs` (Node) скачивает расписание группы
     и сохраняет `public/data/schedule.json`;
  2. GitHub Actions запускает его по cron несколько раз в день (например, в 6:00,
     12:00 и 18:00 по Москве) и коммитит файл, если он изменился;
  3. приложение при открытии подтягивает `data/schedule.json` со своего же сайта,
     сравнивает с сохранённой копией и помечает изменения.
- Если РУЗ недоступен — оставлять прошлую версию файла, не затирать пустотой.
  Никогда не выдумывать пары: пустой день в РУЗ = пар нет.
- Запасной вариант: ручной импорт .ics-файла и ручное добавление пар.
- **Как сделано (этап 1):** разбираем HTML страницы группы (`scripts/ruz-parse.mjs`,
  тест — `npm test`). Ссылка iCal на странице есть, но отвечает перенаправлением (302),
  а в HTML все поля раздельно — поэтому HTML. `oid` 21077 = группа 171606 (проверено).
  Конфиг группы — `src/group.json`. Cron: `.github/workflows/schedule.yml`.
- РУЗ отвечает 403 на запросы из облачной песочницы Claude, но серверам GitHub Actions
  отвечает нормально — проверять загрузку через Actions (кнопка «Run workflow»).
- В расписании есть параллельные потоки/подгруппы (английский — 7 потоков, физкультура,
  «Цифровая культура»): в приложении они показываются карточкой «выбери свою», выбор
  хранится в Dexie (`scheduleRules`, правило `mine` на «предмет + тип занятия»).
- Ещё не сделано из этого раздела: ручной импорт .ics и ручное добавление пар.
- **Календарь для виджета (этап 2.5):** `scripts/make-ics.mjs` + `scripts/ics.mjs` (тесты)
  собирают `public/calendar/171606.ics` перед каждой сборкой (`npm run build`), в git не лежит.

## Дизайн

Референсы стиля лежат в `docs/design/` (две картинки от Максима). Ориентир:

- **Цвета:** фон светлый холодный (#EEF0F8), основной акцент — насыщенный
  фиолетово-синий (#5B3FD9 → градиент до #7B5CF0), карточки белые; вторичный
  акцент — голубой (#3EC5F0) для бейджей; красный только для «просрочено».
  Тёмная тема: фон #15132B, карточки #221E45.
- **Форма:** крупные скругления (карточки 20–24 px, кнопки-«таблетки»), мягкие
  тени, много воздуха, без резких рамок.
- **Шрифт:** геометрический гротеск с кириллицей — Manrope (или Montserrat);
  крупные жирные заголовки, мелкий серый вторичный текст.
- **Узнаваемые элементы из референсов:**
  - шапка экрана «Сегодня» на фиолетовом фоне с приветствием («Привет, Максим»)
    и строкой «3 задания на сегодня»;
  - плитки-счётчики 2×2: «Сделано», «В работе», «Просрочено», «На неделе»;
  - горизонтальная лента дат (кружки-дни) для переключения дня;
  - лента дня: слева колонка времени, справа цветные карточки пар и событий,
    красная линия «сейчас»;
  - нижняя навигация из 4–5 иконок; кнопка «+» для быстрого добавления.
- Mobile-first; на компьютере — боковое меню и две колонки (лента дня + задания).

## Карта экранов

- **Сегодня** — шапка с приветствием, плитки-счётчики, следующая пара с таймером,
  задания на сегодня/завтра, события вечера.
- **Расписание** — лента дат + лента дня; переключатель «день / неделя».
- **Задания** — список с фильтрами; быстрый ввод одной строкой
  («конспект по страхованию до пт», «доклад по истории к следующей паре» — срок
  берётся из расписания с учётом выбранных групп; разбор — `src/lib/quickParse.ts`).
- **Учёба** — предметы → карточка предмета (материалы, конспекты, задания);
  помощники СТО и ГОСТ.
- **Активности** — проекты и события внеучебки.
- **Настройки** — группа, тема, экспорт/импорт, синхронизация.

## Модель данных (черновик)

- `Subject` — id (= name), name, color, contacts, requirements, notes, links[], custom.
  Решение этапа 2: id предмета = его название, задания и конспекты ссылаются на предмет
  по названию (`Task.subject`, `Note.subject`). Так один предмет на телефоне и компьютере —
  одна запись, без дублей при синхронизации; миграция заданий не понадобилась.
  Преподаватели/аудитории/пары берутся из расписания на лету (`src/lib/subjects.ts`).
- `Lesson` — id, subjectId, weekday, start, end, weekParity (all/odd/even), type, room
- `Task` — id, subjectId | projectId, title, dueDate, status, notes, links[], createdAt, updatedAt
  (вместо subjectId — `subject`, название предмета; ещё есть dueTime и doneAt)
- `Note` — id, subject | projectId, title, body (markdown), createdAt, updatedAt.
  Markdown разбирается своим кодом (`src/lib/markdown.ts`, тесты), HTML из текста не вставляется.
- `StoredFile` — файлы и фото (Blob в IndexedDB), ownerType task/subject/note + ownerId;
  фото уменьшаются до 1600 px JPEG. В обычную копию не входят, только в «копию с файлами»
  (base64 внутри JSON). При удалении задания/конспекта файлы удаляются сразу.
- `QuickLink` — библиотеки и сайты; стандартные с постоянными id (`lib:lan` и т. п.).
- `Project` — id, title, kind (council / school / event / rehearsal / other), notes (Markdown),
  archived. Задачи проекта — обычные `Task` с `projectId` (предмет пустой).
- `CalEvent` (таблица `events`) — id, projectId?, title, date, start, end? (нет — 1 час), place,
  notes, seriesId (еженедельный повтор = несколько записей с одним seriesId).
- Нагрузка дня — `src/lib/load.ts`, подсказки — `src/lib/tips.ts` (чистые функции, тесты);
  скрытые подсказки — в kv `tips.dismissed` (только на устройстве).
- У всех записей: `updatedAt` и `deleted` (мягкое удаление — нужно для синхронизации).
- Схема Dexie (`src/lib/db.ts`): v1 — kv, scheduleRules; v2 — tasks;
  v3 — subjects, notes, files, quickLinks; v4 — projects, events; v5 — refs.
- `Reference` (таблица `refs`) — запись списка литературы: taskId ('' — общий список), text,
  data (поля формы). Генератор — `src/lib/gost.ts` (тесты), чек-лист СТО — `src/lib/sto.ts`
  (цифры только из этого файла ТЗ; общие пункты помечены «сверь с методичкой»),
  отметки чек-листа — `Task.stoChecks`. «Спросить Claude» — `src/lib/askClaude.ts`
  (navigator.share с фото/PDF задания, запасной путь — копирование + claude.ai/new).
- Резервная копия (`src/lib/backup.ts`): JSON `{app:'zachetka', format:1, tables:{…}}`,
  при импорте слияние по `updatedAt`. Новые таблицы — добавлять и в копию.

## Правила работы

- Делаем по одному этапу за раз. Перед кодом — короткий план из 3–7 пунктов.
- После этапа: проверить сборку (`npm run build`), обновить галочки в разделе
  «Этапы», сделать коммит с понятным сообщением на русском.
- Не добавлять лишние библиотеки без объяснения, зачем они нужны.
- Не ломать формат сохранённых данных; если меняется схема — писать миграцию Dexie.
- В конце каждой сессии кратко написать: что сделано, как проверить на телефоне,
  что следующее.
